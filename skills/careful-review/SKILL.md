# 复查一次到位

用户抱怨过「每次复核都还有新错」。根因三条：

1. **复查范围只有 diff** —— 每轮只覆盖到「刚改的那几行」，其余等下一轮视角变化才暴露
2. **没有可复跑的判定标准** —— 靠人眼推断，人眼每轮结论可以不同；断言不会
3. **只查「代码写得对不对」，不查「和真上游/真数据对不对」** —— 口径类、覆盖率类问题读代码永远读不出来

收到「复查」类要求时，**必须做完下列 5 项**。缺哪项要**显式说明未做及原因**，不许默认跳过。

## ① 编译 / 类型检查

跑真实的编译或类型检查命令，贴真实结论与关键输出。

- JS/TS：`npx tsc --noEmit`（有分项目配置时用对应的）
- Java：`mvn -q -DskipTests compile`
- 其他：用项目既有命令

⛔ 禁止「应该没问题」「理论上通过」这类表述。

## ② 断言 / 测试报数

跑对应的 harness 或测试，**报出「通过数 : 失败数」**。

- 没有现成 harness 时，**当场补一个最小的** —— 不要求全量覆盖，能判定本次改动的关键路径即可
- 有现成 harness 就全跑，别只跑子集

⛔ 禁止只说「逻辑没问题」。

## ③ 独立复算，三方互证

用**独立于被测代码**的路径算出关键数值，再与代码 / 接口输出比对。

- 可用手段：只读 SQL、第三方探针脚本、手工推算、另一份实现
- ⛔ **不许自证** —— 如果两边都由同一段代码、同一份配置或同一口径推出，那不叫互证

## ④ 边界枚举成表

把边界条件列成表**逐条给结论**，每行写「**输入 → 期望 → 实测**」：

`null` / 空集合 / `0` / 越界 / 脏值 / 未开始 / 无数据 / 无权限 / 早返回分支 / 超时 / 并发 / 默认值与缺省字段

## ⑤ 跨端四处对齐

涉及接口时，这四处必须一致：

**接口字段名与类型 ↔ 消费端 adapter ↔ 类型定义（TS interface / Java DTO）↔ 文案 key**

一处对不上就可能是线上 bug（例如后端字段叫 `pageSize`、前端读成 `size`；或后端返回 `number`、前端按 `string` 解析）。

## 三条禁令

- ⛔ 不许只读 diff 就下「没问题」的结论
- ⛔ 不许把「我判断这段不可达 / 应该走不到」当作已验证
- ⛔ 不许把上一轮自己的结论直接当既成事实 —— 结论也要重新证

## 收尾

查不动的部分**列成「未覆盖项」交回用户**，写清卡在哪、需要什么条件才能查。
⛔ 不许沉默略过。

## 输出格式

按 ①②③④⑤ 分节，每节**先给结论**（✅ / ❌ / ⚠️），**再给证据**（命令 + 输出摘要）。

最后一行汇总：`通过数 : 失败数 | 未覆盖项 N 条`
