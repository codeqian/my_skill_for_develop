# 密钥与敏感信息处置

## 何时使用

- 用户提到 key、token、password、私钥、证书、签名、`.env`
- 要读取配置目录或凭据文件
- 怀疑敏感信息已经写进了某处
- 需要在命令或配置里使用一个密钥

## 四条规则

1. **不读正文**：凭据目录只列文件名。确需使用某个密钥时，只在当次操作中读取，不摘录、不复述、不转存。
2. **不落盘**：不写入记忆、日志、笔记、skill、代码注释、提交信息。
3. **不回显**：回复里不出现任何片段；必要时只说“已配置 / 未配置”“长度 N”。
4. **不复用**：不把密钥复制到另一个文件、另一条命令或命令历史里。

## 需要用密钥时

- 让用户自己在终端设置环境变量
- 文档和示例里用占位符，如 `<TOKEN>`、`${API_KEY}`
- 不把真实值写进任何文件
- 不打印、不 `echo`、不放进 URL 查询参数

## 发现泄漏时

先停下，不要静默删除。按顺序报告：

1. **位置**：文件、行号、是否已提交、是否已推送
2. **类型**：密钥 / 密码 / token / 证书 / 签名
3. **影响范围**：可能被谁读到（本地、远端仓库、日志、CI）
4. **建议**：删除、轮换、清理历史、加 `.gitignore`
5. 等用户确认后再动手

删除文件不等于失效：已暴露的密钥应当**轮换**，尤其是进过 git 历史的。

## 检查清单

- [ ] 没有密钥进入记忆、日志或笔记
- [ ] 回复里没有复现任何片段
- [ ] 示例里使用的是占位符
- [ ] 泄漏已上报，并建议了轮换

## 禁止

- 读取凭据文件的明文内容并展示
- 把密钥写进 skill、注释或提交信息
- 用“先记住，之后再说”的方式暂存密钥
