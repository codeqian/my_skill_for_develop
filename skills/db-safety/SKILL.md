# 数据库操作安全

## 何时使用

- 要连库查数据、写 SQL、改表结构、跑迁移、修数据
- 不确定目标环境是不是生产
- 需要只读核对数据
- 看到 `scripts/*.sql`、migration、`ddl-auto` 之类的东西

## 三条硬规则

1. **不碰生产**：任何测试、探针、验证都不得连接生产库。拿不准是不是生产，先问，不要试。
2. **不破坏表结构**：`DROP` / `TRUNCATE`、删字段、改字段类型或长度、删索引，一律不做，除非用户明确要求。
3. **写操作先确认**：`INSERT` / `UPDATE` / `DELETE` / 任何 DDL，即使是测试库，也必须先拿到确认。

## 动手前先说清

一句话说明：**哪台机器、哪个库、读还是写**。三项缺一项就停下来问。

## 只读探查

- 只发 `SELECT` / `SHOW`
- 大表加 `LIMIT`，不要 `SELECT *`
- 不在只读探查里调用可能写库的函数或存储过程
- 结果只贴关键行，不贴全量数据

## 写操作流程

1. 把准备执行的 SQL 原样贴出来
2. 说明目标表、预计影响行数、是否可回滚
3. 等明确确认
4. 执行后报实际影响行数
5. 失败就停，不要自动重试或换一种写法绕过

## 迁移与 DDL

- 只新增，不破坏既有结构
- 分步走：加列 → 回填 → 切换读写 → 清理旧结构（清理单独确认）
- 大表变更先说明锁表风险与预计时长
- 不使用“先提交一版再验证”的方式

## 禁止

- 用生产库做测试或探针
- 为了把验证跑起来而启动应用（可能触发 `ddl-auto` 改表）
- 把连接串、密码、token 写进回复、记忆或日志

## 输出

- 目标：机器 / 库 / 读写性质
- 语句或操作
- 结果：影响行数、耗时、失败原因
- 未覆盖项：没查的部分和原因
